# BUTDETAL 2.0.6 — Android-проєкт

Україномовний довідник для будівельника з офлайн-інтерфейсом, калькуляторами, каталогом, архівами фото/креслень, PDF та OCR.

## Збірка APK
1. Відкрий кореневу папку проєкту в Android Studio (де `settings.gradle`).
2. Встанови Android SDK Platform 35 та Build Tools 35.0.0.
3. Дочекайся Gradle Sync, потім виконай **Build → Build APK(s)**.
4. Debug APK буде у `app/build/outputs/apk/debug/app-debug.apk`.

Або завантаж проєкт у GitHub і запусти workflow **Build BUTDETAL APK** у вкладці Actions. Workflow спочатку перевірить наявність методів AndroidStorage та мовних файлів OCR, а потім спробує зібрати APK.

## OCR
Підтримуються українська, російська та англійська мови. PDF рендериться посторінково Android PdfRenderer; у поточному коді за один запуск обробляється не більше 40 сторінок. Для тесту вибери чіткий PDF або фото креслення в розділі армування.

## Важливо
Це вихідний код, а не перевірений APK. Статична перевірка не замінює Gradle-збірку та тест на реальному телефоні. Після складання потрібно перевірити: OCR PDF/фото, збереження й відкриття PDF, архів фото, імпорт/експорт XLSX та авторизацію Supabase. Хмарна синхронізація не запрацює, доки не буде налаштовано власний Supabase URL, публічний ключ, таблиці та політики доступу.

Файли, що зберігаються у приватному сховищі застосунку, можуть бути видалені разом із самим застосунком. Важливі креслення зберігай окремо. Інженерні розрахунки довідкові й мають перевірятися за робочими кресленнями та чинними нормами.


## Автоматичні оновлення 2.0.6

Застосунок перевіряє GitHub Releases під час запуску. Якщо знайдено новіший реліз із APK, з'являється кнопка завантаження; APK завантажується Android DownloadManager, після чого відкривається системний інсталятор. Android вимагає одноразово дозволити встановлення невідомих застосунків для BUTDETAL та підтверджувати встановлення кожного оновлення.

Для публікації підписаних оновлень налаштуйте в GitHub → Settings → Secrets and variables → Actions такі secrets: `BUTDETAL_KEYSTORE_BASE64`, `BUTDETAL_KEYSTORE_PASSWORD`, `BUTDETAL_KEY_ALIAS`, `BUTDETAL_KEY_PASSWORD`. Використовуйте одну й ту саму приватну keystore для всіх майбутніх версій; не додавайте її до репозиторію. Потім створюйте тег релізу, наприклад `v2.0.7`. Workflow збере й опублікує APK.

**Важливо щодо першого переходу:** оновлення Android встановлюються лише APK з тим самим сертифікатом підпису. Якщо раніше встановлений APK був підписаний іншим debug-ключем, нову версію поверх нього встановити не вдасться. Потрібно один раз встановити 2.0.6 вручну; перед цим слід перевірити сумісність підпису та зберегти резервну копію даних. Після переходу всі оновлення мають використовувати той самий keystore.


## Резервне копіювання (2.0.6)

У розділі «Архів» доступні кнопки створення та відновлення резервної копії. ZIP містить локальні робочі дані WebView, фото/креслення, PDF та JSON-метадані. Дані входу, пароль і активний сеанс не експортуються з міркувань безпеки; після відновлення потрібно увійти повторно. Зберігайте ZIP окремо від телефона. Перед переходом на інший ключ підпису спочатку створіть копію та перевірте, що ZIP відкривається.

**Важливо:** це резервування працює лише в цій оновленій збірці. Воно не може бути додане до вже встановленого APK 2.0.4 без сумісного ключа підпису. Не видаляйте старий застосунок, доки не буде підтверджено безпечний спосіб перенесення його даних.


## Версія 2.0.7

Додано створення ZIP-резервної копії та відновлення локальних робочих даних. Нативний міст передає JSON частинами, щоб зменшити ризик перевищення ліміту Binder. Перевірено статично та перевірено синтаксис JavaScript. Компіляція Android і робота на фізичному пристрої ще не підтверджені.


## Supabase — налаштування 2.0.8

У цій збірці URL проєкту та Publishable key задані як клієнтська конфігурація за замовчуванням. Secret/service_role key не використовується. Після встановлення адміністратор має створити користувача в Supabase Auth і виконати SQL-схему з комплекту налаштування.

Поточна синхронізація Supabase охоплює каталог виробів (`shared_records`, `record_type=product`). Фото, креслення та PDF у цій версії залишаються в локальному архіві телефону; серверне завантаження/синхронізація цих файлів ще не реалізовані. Перед робочим використанням потрібне тестування на окремому тестовому обліковому записі та перевірка RLS-політик.


## Синхронізація архіву Supabase (2.0.8)

1. У Supabase SQL Editor виконай `SUPABASE_SYNC_MIGRATION.sql` після початкового `SUPABASE_SETUP.sql`.
2. У застосунку кожен користувач входить своїм раніше створеним обліковим записом.
3. Натисни «Синхронізувати каталог і файли». Картки каталогу, фото, креслення та PDF передаються у приватний Storage bucket `butdetal-archive`; файли інших працівників завантажуються в локальні папки.
4. Локальні файли не видаляються при синхронізації. Для офлайн-доступу використовуються локальні копії.

Примітки: синхронізація запускається вручну або після входу; це перша реалізація без автоматичного фонового планувальника. Потрібно перевірити на реальних двох пристроях. Не видаляй попередню встановлену версію, поки не зроблено резервну копію.
